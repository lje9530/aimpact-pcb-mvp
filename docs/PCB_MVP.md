# 실행·운영 매뉴얼

## 실행과 저장 위치

설치는 [README의 빠른 시작](../README.md)을 따릅니다. YOLO 모드의 기본 기록은 `outputs/inspections-yolo.sqlite3`에 저장됩니다. 처음 열면 DeepPCB 예제 12건과 시연용 담당자 판정 4건을 불러옵니다.

현재 기록을 보관한 채 새 시연을 시작하려면 실행 명령에 `--database outputs/rehearsal.sqlite3`를 붙입니다. 빈 화면에서 협력사 업로드부터 시연하려면 새 DB 경로와 `--empty`를 함께 사용하세요. 앱 종료는 터미널에서 `Ctrl+C`입니다.

```powershell
.\.venv\Scripts\python.exe run.py --database outputs/rehearsal.sqlite3
```

## 검사 흐름

| 단계 | 사용 방법 |
|---|---|
| 바로 검사 | `PCB 이미지 검사`에서 표시 없는 검사 영상 한 장을 선택하면 YOLO가 검출한 박스와 유형이 표시됩니다. |
| 가져오기 | 협력사명과 검사 기록 CSV·XLSX, 검사·기준 영상 파일을 선택합니다. `열 매핑 불러오기`에서 공통 항목을 연결합니다. |
| 근거 확인 | 박스를 클릭하면 해당 위치가 확대됩니다. `탐지 박스`를 끄면 입력 영상을 확인할 수 있습니다. 기준 영상이 있으면 `나란히 비교`와 `차이 보기`를 사용할 수 있습니다. |
| 판정 저장 | 정상·불량 및 해당 유형, 담당자를 입력합니다. 선택적으로 메모를 남기며, 반복 저장 시 각 판정 차수가 이력에 추가됩니다. |
| 현황·조회 | 현황에는 확정 유형, 일자별 검사, 반복 불량이 집계됩니다. 이력의 제품·기간·유형 필터를 적용한 뒤 엑셀을 내려받을 수 있습니다. |

## 업로드 규칙

- 필수 항목은 **제품코드, 검사일시, 검사 영상 파일명**입니다. 검사 ID, 공정, 로트, 협력사 판정·유형, 기준 영상 이름을 추가할 수 있습니다.
- `2026-11-23`이나 `2026-11-23 09:00:00`처럼 날짜를 표기합니다. XLSX는 활성 워크시트를 읽고 파일의 첫 행을 열 이름으로 사용합니다.
- 표에 적힌 검사·기준 영상 파일명을 첨부 파일의 이름과 일치시킵니다. 선택 항목인 기준 영상은 검사 영상과 해상도가 같아야 합니다. 픽셀 차이를 비교할 때는 같은 제품 패턴을 같은 시야와 배율에 정렬한 쌍을 사용합니다.
- 가져오기는 선택한 모든 행을 검증한 뒤 저장합니다. 협력사와 검사 ID가 같은 건은 중복 처리합니다. ID가 없으면 제품·일시·공정·로트·영상 파일명으로 식별합니다.
- ROI는 선택 항목입니다. 0~1 사이의 `x, y, 너비, 높이`를 입력하면 해당 업로드에 공통으로 적용됩니다. 예를 들어 `0.1, 0.1, 0.8, 0.8`은 중앙 80% 영역입니다.

업로드 창의 **업로드 예제 ZIP**에는 바로 가져올 수 있는 표와 일치하는 영상 파일이 들어 있습니다. 예제의 `품번 → 제품코드`와 `aoi_file → 검사 영상 파일명` 연결을 보여주면 매핑 기능을 짧게 시연할 수 있습니다.

## 점수와 집계 기준

작업대의 점수는 가장 높은 후보의 비보정 분류 점수입니다. 현황에서 `담당자 확인 기준`을 변경하면 해당 점수보다 낮은 검토 대기 건이 `확인 필수`로 표시됩니다. 모델 점수가 없는 대기 건도 확인이 필요합니다. 최종판정은 담당자가 저장합니다.

`AI·담당자 일치`는 AI 초안과 담당자의 정상·불량 결과가 같은 비율입니다. 보류 건은 분모에서 제외됩니다. `반복 불량`은 동일 제품에서 같은 불량유형이 두 건 이상 확정된 경우입니다. 판정에 선택된 복수 유형은 각각 집계합니다.
